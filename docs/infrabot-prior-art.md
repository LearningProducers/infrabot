# infrabot — repository lineage and public prior-art dossier

A dated, commit-anchored working record of **infrabot**, a single-file browser application by Learning Producers, Inc., published as source under the MIT license at [LearningProducers/infrabot](https://github.com/LearningProducers/infrabot). It follows the house format of the [Combat Writing dossier](https://github.com/LearningProducers/CombatWriting/blob/main/docs/combat-writing-prior-art.md), which is in turn modeled on the account-wide prior-art dossier kept for the [ruvnet](https://github.com/ruvnet/ruvnet/blob/main/docs/ruvnet-prior-art.md) GitHub account, and it keeps the same separation between kinds of evidence:

- **Repository lineage:** a root commit proves that a repository's history contains that commit and its self-asserted Git author date. It does not by itself prove when GitHub first served the commit, when the repository became public, or when a later feature appeared. Repository `created_at`, pull-request timestamps, commits signed by GitHub's own web-flow key, and independent archives are stronger public-appearance evidence.
- **Claimed novelty (scoped candidate):** where the application appears to contain a first-of-its-kind combination, the claim is written as an explicit predicate with named prior art and a confidence level. A commit is a lineage anchor, not by itself proof that every current feature existed at that commit; the feature-genesis table below ties each feature to the first commit whose source contains it.

Confidence reflects how defensible the scoped predicate is against the named prior art after a non-exhaustive related-work review. Git author dates are self-asserted; where a commit was created through GitHub's web interface (a browser upload or edit, or a pull-request merge) its committer timestamp was set by GitHub's servers, and those rows are marked.

> **Technical and legal scope:** This is a technical provenance record and non-exhaustive related-work review, not a patentability, inventorship, freedom-to-operate, trademark, or legal prior-art opinion. Items published after a claim's cutoff date are subsequent related work, not prior art against that cutoff. Copyright in the application subsists independently of this document; this document grants no license beyond the repository's own.

> **Rights:** The public repository carries the MIT License, copyright 2026 Learning Producers, Inc., added by the second public commit on 2026-07-30. Third-party components (Groq's API and the models served through it, which at the record date are an OpenAI open-weight model family and a Qwen model family) belong to their providers under their own terms.

> **Privacy scope of this record:** This document names the application's author, because authorship is part of what a provenance record has to establish. It names no other individuals and contains no email addresses, prospects, companies contacted, contacts, send dates, correspondence, or internal Learning Producers records. The application is an outreach tool, so its operating data is exactly the kind of thing this record leaves out. Changes are described in product terms. Commit rows for the private origin repository carry the hash, the recorded author date, the app version, the content hash and size of the app file, whether GitHub's server set the timestamp, and the kind of file the commit touched; they do not quote that repository's commit messages. The names of internal working documents that the origin repository tracked are listed so the file inventory is complete; their contents are not described.

Record date: **2026-09-27**. Figures marked "as of the record date" are snapshots and will drift.

## Lineage at a glance

- **What the application is:** one `infrabot.html` (no build step, no dependencies beyond a browser and Python 3) plus a small standard-library Python server bound to loopback. It is an outreach console built around one rule: an AI agent researches prospects and drafts the messages, an in-browser "council" of two language models critiques and revises the drafts, and **the human sends every message by hand from their own mail client**. There is no send button and no mail integration by design. The agent's work reaches the page as a plain-text file of labeled prospect blocks (or through the same parser via an import button) and, since v0.5.0, through a loopback JSON "state door" with a revision number. Cards move DRAFT → SCHEDULED → SENT → REPLIED; a sent card with no reply after five days is marked WENT QUIET automatically; CLOSED is the human's call. Around the cards: a world map with contact-local clocks, a two-tier network of people (acquaintance or contact), in-person events ("rooms") with a required line saying why the room is worth attending, an artifact ledger, monthly reports, a full-state JSON export with the API key stripped, and a reconcile script that writes statuses and dates into a tracker CSV whose Notes column the tool never touches. The repository's own one-line description: "Agent-first outreach console: your AI agents do the researching, you do the sending."
- **Public repository:** [LearningProducers/infrabot](https://github.com/LearningProducers/infrabot), created **2026-07-30T15:18:30Z** (GitHub `created_at`), public, MIT license, no GitHub Pages. ### Provenance mechanisms and what they achieve
- USPTO MPEP §2128: an internet publication is a printed publication as of the date it was publicly posted; an undated page cannot be relied upon. 35 U.S.C. §102(b)(1)(A): an inventor's own disclosure starts a one-year United States grace period; most other jurisdictions apply absolute novelty.
- *Valve Corp. v. Ironburg Inventions*, 8 F.4th 1364 (Fed. Cir. 2021-08-17): Wayback Machine captures accepted as evidence of public accessibility.
- Software Heritage "Save Code Now" (2019-01-10) and SWHIDs, standardized as ISO/IEC 18670:2025 (2025-04-23): independent archival date and content integrity; does not validate the dates inside the repository.
- Zenodo–GitHub release archiving with DOIs (since 2014). OpenTimestamps (2016-09-15): a proof that a hash existed before a Bitcoin block; proves existence, not authorship or public accessibility.
- GitHub commit signature verification: a "Verified" badge binds a commit to a key; author and committer dates on locally made commits come from the local clock and are displayed without validation. Server-side events (repository and pull-request timestamps, releases) are the independent dates.
